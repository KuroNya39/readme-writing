# readme-writing

为软件项目撰写 / 重写 / 同步 README 与用户指南——可装进 AI agent 的 Skill。

AI 先替开发者把项目读明白：提取功能清单、推断读者、重建上手路径、审计数据与隐私、抄录界面文案与产品专名原文，产出可溯源的《事实清单》；只把「只有开发者知道的取舍」抛给你判断（每题带推荐答案，可整轮回「全按推荐」）；再由读者心智推导结构、起草全文，校验后交付。

## 安装

把下面这段话发给你的 AI agent：

> 把 https://github.com/KuroNya39/readme-writing 装成我的 skill：仓库里的 `SKILL.md` 放进你的 skills 目录，目录名用 `readme-writing`。装好后告诉我怎么确认它生效了。

装完重开一次 agent；想升级，跟它说「把 readme-writing 更新到最新」。

## 调用

- **直接说人话**：「用 readme-writing 给这个项目写一份 README」——带上 skill 名最稳，不带也多半能认出来
- **斜杠命令**（支持的 agent）：`/readme-writing`

## 适用场景

- 新项目写第一版 README / 用户指南
- 旧文档乱、读者看不懂，要从开发者笔记改成用户文档
- 软件改了 UI / 流程 / 文案 / 数字后回来同步

## 工作方式

按 A–F 六个阶段推进，全程半自动：

| 阶段 | 做什么 |
|---|---|
| **A · 侦察取证** | 读代码与运行画面，产出每条可溯源的《事实清单》；界面文案与产品专名按官方写法原文抄录 |
| **B · 决策轮** | 只问代码答不了、只有开发者知道的取舍，每题带推荐答案，可整轮「全按推荐」 |
| **C · 信息架构** | 按读者心智顺序推导章节，不套模板；同一条信息只在一节写全 |
| **D · 写作** | 起草全文：结论先行、可扫读、界面文案用「」引用；加粗只用于条目术语 / 粗体小标题 / 关键句三种用途 |
| **E · 校验** | 可走通性 / 事实 / 文案 / 隐私 / 可读性 / 去重 / 记号系统七项自检，未通过不出稿 |
| **F · 交付维护** | 先骨架后正文；UI / 流程 / 文案变更后回取证同步受影响的节；推荐值与示例命令要与软件逐字一致，专名改动扫一遍对外呈现面 |

## 它不做

- **不编内容** —— 每个数字、承诺、界面文案都能溯源到 `file:line` 或界面原文
- **不问你查得到的事** —— 能自己查的事实自己查，只把真正的取舍抛给你
- **不静默改对外文档** —— 已存在的文档，改动先给你看「改哪句、改成什么样」

## 目录

- `SKILL.md` —— 阶段 A–F 全文（取证清单、提问格式、写作规则、自检清单）
